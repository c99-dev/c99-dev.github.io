# 운영 배포

대표 주소는 `https://aram.c99-dev.com/`입니다. OCI Ubuntu ARM 서버의 nginx가 정적 파일을 제공하며, 기존 한글 주소는 경로와 쿼리를 유지하여 대표 주소로 301 이동합니다. 디자인과 데이터 형식은 그대로입니다. 주소가 달라졌으므로 기존 브라우저의 밴·옵션 저장값은 새 주소로 자동 이전되지 않습니다.

## 자동 배포

`main` 푸시 또는 `main`에서 workflow 수동 실행 시 `.github/workflows/deploy.yml`이 동작합니다. PR 검증과 운영 빌드 모두 GitHub 호스팅 runner에서 실행합니다. OCI에 runner나 npm 의존성을 설치하지 않습니다.

1. 잠긴 npm 의존성과 Python 검사 의존성 설치
2. JavaScript/Python 테스트 및 기존 챔피언 데이터 검증
3. GA4 설정을 검사한 뒤 Vite 운영 빌드
4. 제한된 SSH 배포 계정으로 압축된 정적 파일 전송
5. 서버에서 파일 경로·대표 주소·GA4·필수 파일을 검증한 뒤 운영 링크 교체
6. 내부 응답이 실패하면 이전 운영 링크 복구, 외부 HTTPS 응답의 커밋 확인

Repository variables:

- `REACT_APP_GA_TRACKING_ID`: 기존 GA4 측정 ID
- `OCI_HOST`: OCI 공인 IP
- `OCI_KNOWN_HOSTS`: 기존 관리자 SSH 연결로 확인한 서버의 SSH 공개 호스트 키

Repository secret:

- `OCI_DEPLOY_KEY`: 이 사이트에만 사용하는 SSH 개인키

배포 키는 마지막 단계에만 제공하며 로그로 출력하지 않습니다. 서버의 `aram-deploy` 계정에는 sudo, Docker, 포트 포워딩, 대화형 셸 권한을 주지 않습니다. SSH forced command는 `deploy <40자리 SHA>`만 받고 관리자 소유의 `/usr/local/lib/aram-deploy/receive_deployment.py`를 실행합니다. 업로드한 파일을 코드로 실행하지 않으며, 사이트 배포 경로 안에서만 파일을 작성합니다. 관리자 스크립트를 수정하려면 별도 관리자 SSH 접근이 필요합니다.

## 서버 경로

- 배포 계정 홈: `/srv/aram-deploy` (관리자 소유)
- 배포 버전: `/srv/aram-random-pick/releases/`
- 운영 링크: `/srv/aram-random-pick/current`
- 새 주소 nginx 설정: `/etc/nginx/sites-available/aram-random-pick`
- 기존 주소 nginx 설정: `/etc/nginx/sites-available/aram-legacy`
- 배포 버전 확인: `https://aram.c99-dev.com/deployment.json`
- 내부 확인: `http://127.0.0.1:8088/deployment.json`

기존 Tailscale Serve와 충돌하지 않도록 HTTPS는 OCI NIC인 `10.0.0.114:443`에 바인딩합니다. nginx 설정 변경은 `nginx -t` 성공 후 reload하며, 앱 파일 배포에는 nginx 재시작이 필요하지 않습니다.

## DNS·인증서·검색

새 주소는 Cloudflare의 DNS only A 레코드로 OCI를 가리킵니다. 기존 주소는 내도메인.한국에서 관리합니다. 기존 도메인도 HTTPS 요청에 응답한 뒤 리디렉션해야 하므로 인증서를 계속 유지합니다. 인증서 갱신에는 기존 certbot timer와 nginx reload 훅을 사용합니다.

HTML의 canonical, Open Graph 주소, 구조화 데이터, sitemap은 새 주소를 사용합니다. Search Console은 이전·새 주소 모두의 소유권을 확인하고 주소 변경을 제출합니다. GA4는 기존 속성과 측정 ID를 유지합니다. 기존 주소의 301은 최소 1년 이상 유지하며 가능한 한 계속 운영합니다.

GitHub Pages의 `gh-pages` 브랜치와 기존 도메인 연결은 전환 중 복구 및 기존 GitHub 주소 이동을 위해 보존합니다. 이 저장소의 `main`은 더 이상 Pages로 직접 배포하지 않습니다.

## 복구

관리자 SSH로 `current`의 대상과 `releases`의 이전 버전을 확인합니다. 확인한 이전 버전을 가리키는 임시 심볼릭 링크를 만들고 `mv -Tf`로 `current`를 교체합니다. 이후 내부 및 외부 `deployment.json`의 커밋과 홈페이지를 확인합니다. 현재 버전과 복구 후보는 삭제하지 않습니다.

외부 네트워크 검사만 실패한 경우 Actions 로그와 nginx·DNS·HTTPS 상태를 먼저 확인합니다. 내부 검사는 성공했을 수 있으므로 무조건 이전 버전으로 덮어쓰지 않습니다. DNS 전환 자체를 되돌릴 때는 기존 한글 주소의 원래 A 레코드 `185.199.108.153`과 보존된 GitHub Pages 상태를 함께 확인합니다.
